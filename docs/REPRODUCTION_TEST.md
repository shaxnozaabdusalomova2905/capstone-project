### What went wrong the first time

The demo failed with `Could not find models/resnet18_config.json`.

Two causes, one hiding the other. The model weights had not been pushed to GitHub yet, and the repository was still private, so an anonymous clone was refused. The code used `git clone --quiet` and threw away the error message, so the real reason never appeared.

### What was fixed

- The clone now captures git's actual error and prints it, instead of failing silently
- The repository was made public
- The model weights were committed, so a clone brings everything needed

Only **fold 2** of ResNet18 is committed. All five folds would add over 220 MB; one fold is enough to make predictions, and the rest are regenerated by re-running notebook 04.

### Still to do

**The restart step.** The saved run happened in a session where the repository was already present, so its output shows `Repository : /content/capstone-project` without the `Cloning...` line. The clone was seen working live, but the *saved* notebook does not prove it.

One run closes this: open notebook 05 in a brand-new Colab session, choose **Runtime → Restart**, run every cell from the top, and save. That records the restart and captures the clone line in the same pass.

### Remaining limitation

Re-running the **training** notebooks will not reproduce the numbers exactly. GPU training is not perfectly repeatable — running notebook 03 twice gave macro F1 of 0.576 and then 0.583. The folds are identical every time because the random seed is fixed, but small differences in the trained weights remain.

Adding `torch.backends.cudnn.deterministic = True` would remove this, at a small cost in training speed. It was not applied retrospectively, because re-running would have produced a third set of numbers and meant rewriting every recorded observation again.

This does not affect the demo. It loads saved weights and gives the same answer every time.
